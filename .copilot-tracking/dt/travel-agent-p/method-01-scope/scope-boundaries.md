## 요청 분류

- 분류: **Frozen** — "일정 자동 설계 앱"이라는 특정 해법을 이미 확정한 상태로 도착
- 원래 요청: 조건 3개(도시·기간·동행) 입력 → 2박3일 일정 자동 생성
- 발견된 문제 공간: "추천 정보 부족"이 아니라 **"흩어진 정보를 시간표로 조립하는 노동"**
- 간극: 원래 요청은 *추천*을 팔고, 실제 문제는 *조립*을 요구함

## In Scope

- 도시·기간·동행 입력 → 일정 생성
- 이동 동선 고려 (생성 시점 필터링)
- 일정 JSON 반환
- 최소 웹 UI

## Out of Scope

- 실제 예약 / 결제
- 항공권 발권
- 다국어
- 로그인 / 계정
- 모바일 네이티브 앱
- **생성된 일정 수정 루프** (2026-09-16 제외)
  - 같은 날 In Scope로 편입했다가 제외됨
  - 제외 근거: HMW2(생성 시점 동선 필터링)에 흡수. 사후 수정으로 동선 실패를 메꾸는 대신 애초에 생기지 않게 하는 방향
  - 부수 효과: 생성 품질이 어긋났을 때 복구 수단이 없어짐

## 제약 — Frozen vs Fluid 분류 (2026-09-16 확정)

| 구분 | 제약                          | 분류   | 메모                                        |
|------|-------------------------------|--------|---------------------------------------------|
| 물리 | 이동 중 모바일 사용           | Frozen | 환경 자체는 바꿀 수 없음                    |
| 물리 | 소음 · 한손 조작              | Frozen | UI 설계를 강제하는 조건                     |
| 물리 | 데이터 로밍 불안정            | Frozen | 오프라인 내성 여부가 설계 갈림길            |
| 운영 | 여행 전날 밤 급하게 사용      | Frozen | 사용 시점이 성능 요구를 규정                |
| 운영 | 일정 변경이 잦음              | Frozen | 현실이지 선택지가 아님                      |
| 운영 | 동행자와 합의 필요            | Frozen | 현실 — 다만 제품이 대응할지는 미결          |
| 기술 | 해커톤 2일                    | Frozen | 협상 불가                                   |
| 기술 | LLM 응답 10초 이내            | Frozen | 절대 기준으로 확정                          |
| 기술 | 지도 API 무료 티어            | Frozen | 유료 전환 없음 — 호출 예산이 고정됨         |
| 기술 | 예약 API 연동 불가            | Frozen | Out of Scope와 일치                         |

### 제약 전부 Frozen일 때의 파급

- 10초 상한 + 무료 티어 호출 예산 = **일정 1건당 LLM 왕복과 지도 호출 횟수가 사실상 고정**
- 따라서 "수정/합의 루프"를 넣으면 그 예산을 N배로 곱하게 됨 → 루프 설계는 재생성이 아닌 다른 방식이어야 함
